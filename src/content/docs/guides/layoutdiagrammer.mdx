## Planlæg din HTML med et layoutdiagram

Et **layoutdiagram** viser, hvilke kasser din side består af, hvilke kasser der ligger inden i andre, og hvor du vil bruge grid.

Du tager udgangspunkt i dine **wireframes til både mobil og desktop**. En prototype kan også bruges som grundlag.

1. Sammenlign de to layouts.
2. Tegn kasser om elementer, der skal høre sammen.
3. Skriv de planlagte **class-navne øverst i kasserne**.
4. Oversæt kasserne til HTML, tilføj CSS, og test resultatet.

Diagrammet hjælper dig med at beslutte strukturen, før du begynder at kode.

## Fra de store kasser til HTML

Den yderste `.grid_2-1` har **to direkte børn**: `.indhold` og `.ekstra`. Det er dem, der bliver hovedkolonnerne på desktop.

```html
<main class="side">
  <h1>Sidens overskrift</h1>
  <div class="grid_2-1">
    <div class="indhold">
      <section class="grid_1-2">
        <!-- Billede 1 og tekst 1 -->
      </section>
      <section class="grid_2-1 bytter">
        <!-- Billede 2 og tekst 2 -->
      </section>
    </div>
    <section class="ekstra">
      <!-- Billede 3 og tekst 3 -->
    </section>
  </div>
</main>
```

De to sektioner i `.indhold` ligger inde i den venstre hovedkolonne. **Hvert grid styrer sine egne direkte børn.**

`grid_2-1 bytter` er to classes på samme element. I diagrammet står det som `.grid_2-1.bytter`.

## Gruppér den tekst, der skal følges ad

Inde i den første sektion skal overskrift og afsnit ligge i **samme tekstkolonne**. Derfor får de en fælles `.tekst`-kasse:

```html
<section class="grid_1-2">
  <img class="billede" src="images/foto-1.webp" alt="Udsigt over havnen" />
  <div class="tekst">
    <h2>En tur ved havnen</h2>
    <p>Følg vandet, og oplev byen til fods.</p>
  </div>
</section>
```

Her har grid-containeren **to direkte børn**: billedet og tekstkassen. `h2` og `p` bliver inde i tekstkassen.

Brug samme indre struktur i de andre sektioner. Billeder og tekster skal selvfølgelig passe til dit eget indhold.

**Vælg HTML-element efter betydning:** En `section` samler et emne med en overskrift. En `div` kan samle elementer af hensyn til layoutet.

## Giv class-navnene deres layout i CSS

Navnet `.grid_1-2` er vores huskeregel for kolonneforholdet. **Et class-navn laver først et grid, når vi skriver CSS til det.**

<div class="columns-2">
<div>

**Grundregler · mobil**

```css
.side {
  max-width: 1100px;
  margin-inline: auto;
  padding-inline: 1rem;
}

.indhold > * + *,
.ekstra > * + *,
.grid_1-2 > * + *,
.grid_2-1 > * + * {
  margin-top: 1.5rem;
}
```

Indholdet følger HTML-rækkefølgen i én kolonne. Brug også [en reset og fleksible billeder](/guides/code-recap/#start-css-med-en-grundlæggende-reset).

</div>
<div>

**Udvidelse · desktop**

```css
@media (min-width: 800px) {
  .grid_1-2,
  .grid_2-1 {
    display: grid;
    gap: 1.5rem;
    align-items: start;
  }

  .grid_1-2 {
    grid-template-columns: 1fr 2fr;
  }

  .grid_2-1 {
    grid-template-columns: 2fr 1fr;
  }

  .grid_1-2 > *,
  .grid_2-1 > * {
    margin-top: 0;
  }
}
```

</div>
</div>

`800px` er et eksempel. Find et breakpoint, hvor **dit indhold** har plads til kolonnerne.

## Når billede og tekst bytter plads

I PowerPointens andet indholdsområde står **billede 2 før tekst 2 på mobil**. På desktop står teksten til venstre og billedet til højre.

Behold mobilrækkefølgen i HTML, og tilføj disse regler til desktop-layoutet:

```css
@media (min-width: 800px) {
  .bytter > .billede {
    grid-column: 2;
    grid-row: 1;
  }

  .bytter > .tekst {
    grid-column: 1;
    grid-row: 1;
  }
}
```

Classen `.bytter` sidder på sektionen med `class="grid_2-1 bytter"`. Begge børn placeres i **samme række**.

CSS ændrer den visuelle placering. Læse- og tastaturrækkefølgen følger stadig HTML, så indholdet skal give mening i den rækkefølge. Læs om [grid og læserækkefølge hos MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout/Accessibility).

## Tredje trin: Byg, test og ret til

Byg først strukturen med korte tekster og billeder, så du kan undersøge layoutet. Fyld derefter det endelige indhold ind.

Tjek både mobil, desktop og bredderne imellem:

- Passer **kasserne inden i hinanden** med din HTML?
- Står de rigtige class-navne både i diagrammet og i koden?
- Placerer hvert grid de børn, du havde tænkt dig?
- Følger indholdet en logisk rækkefølge på mobil?
- Virker layoutet også med længere tekster og dine egne billeder?

**Ret både diagram og kode**, hvis du finder en bedre struktur. Diagrammet er en plan, du kan forbedre undervejs.

Fortsæt med dit eget emnesite, og brug [Code recap](/guides/code-recap/) som tjekliste. Se også [CSS Grid](/css/grid/).
