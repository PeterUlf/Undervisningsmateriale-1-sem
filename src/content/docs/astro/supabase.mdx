## 1) Log ind på Supabase med GitHub

Inden du kan bygge videre, skal du logge ind i Supabase med din GitHub-konto.

1. Gå til [Supabase Dashboard](https://supabase.com/dashboard).
2. Klik **Continue with GitHub** og gennemfør login.
3. Du står nu i Supabase med adgang til projekt og database.

Når du er logget ind, kan du gå videre til at oprette tabellen.

</Slide>

## 2) Opret en tabel i Supabase

Du kan oprette en tabel på to måder:

1. I Supabase Dashboard:
   1. Gå til `Table Editor`
   2. Klik `Create a new table`
   3. Navngiv tabellen fx `students`
2. Via SQL (men det gør vi ikke nu)

Efter oprettelse kan du tilføje testrækker i `Table Editor`.

</Slide>

## 2a) Datatyper i Supabase

Når du laver en kolonne i en tabel, skal du vælge en datatype.

### Datatypen bestemmer, hvilken slags værdi kolonnen må indeholde.

| Datatype    | Bruges til         | Eksempel                                |
| ----------- | ------------------ | --------------------------------------- |
| `text`      | almindelig tekst   | `first_name`, `last_name`, `class_name` |
| `uuid`      | unikt id           | `id`                                    |
| `integer`   | hele tal           | `age`, `semester`                       |
| `boolean`   | ja/nej             | `is_active`                             |
| `date`      | dato               | `birth_date`                            |
| `timestamp` | dato og klokkeslæt | `created_at`                            |

### Til tabellen `students` vil du typisk vælge:

| Kolonne      | Datatype |
| ------------ | -------- |
| `id`         | `uuid`   |
| `first_name` | `text`   |
| `last_name`  | `text`   |
| `email`      | `text`   |
| `class_name` | `text`   |

</Slide>

## 2b) Data API og automatic RLS

Når I opretter tabellen i undervisningen, så vælg:

- **Enable Data API: ON**
- **Enable automatic RLS: ON**

</Slide>
<div class="page-break"></div>

<Slide>

## Enable Data API

Tænder for REST-adgang til tabellen via Supabase URL (`.../rest/v1/<tabel>`).
Hvis den er slået fra:

- findes endpointet ikke i API.
- kan din `fetch()`-kode ikke hente data fra denne tabel.

Det betyder altså, at tabellen kan bruges i de `fetch()`-eksempler, I arbejder med i Tema 9.

</Slide>
<div class="page-break"></div>

<Slide>

## Enable automatic RLS

Slår Row Level Security (RLS) til med en initial sikkerhedsopsætning.

- Hvis RLS er ON, gælder politikker (policies), før data sendes tilbage.
- Hvis der **ikke** findes en policy, kan anonyme eller loggede kald få afslag (`permission denied`).
- Hvis RLS er OFF, kan tabellen være mere åbent tilgængelig — nemt til test, men mindre sikkert.

Det betyder, at de studerende lærer den rigtige sikkerhedsmodel fra start:

- data er ikke automatisk åbne
- adgang styres med policies
- I kan senere koble det sammen med login og brugerroller

Kort anbefaling:

- slå begge til
- lav derefter en policy, hvis tabellen skal kunne læses i jeres øvelser

</Slide>

## 3) Find den rette Supabase endpoint

REST-endpointet for en tabel ser sådan ud:

```text
<Project URL>/rest/v1/<tabelnavn>
```

Find værdierne i Supabase:

- **Project URL**: `Settings → API → Project URL`
- **Publishable Key**: `Connect → API Keys → Publishable Key`

`Anon Key (legacy)` er den gamle nøgletype. I nyt undervisningsmateriale er det bedre at lære de studerende at bruge **Publishable Key** først.

Eksempel:

- `https://abcdefgh.supabase.co/rest/v1/students`

For at vælge felter og sortere:

- `.../rest/v1/students?select=id,first_name,last_name,class_name&order=first_name.asc`

</Slide>
<div class="page-break"></div>

<Slide>

## Endpoint

### direkte i browseren, giver en fejl der minder om dette:

```json
{
  "message": "No API key found in request",
  "hint": "No `apikey` request header or url param was found."
}
```

### Det betyder:

- du har fundet den rigtige URL
- men Supabase vil ikke vise data uden en API-nøgle
- browserens adresselinje sender ikke automatisk en `apikey` header

</Slide>
<div class="page-break"></div>

<Slide>

## Endpoint

### for at se data skal du

1.  Brug `fetch()` og send `apikey` i headers

<div style="margin-top: 1.5rem;"></div>

### Eller hvis du bare lige skal teste direkte i browseren:

Hvis du vil ha lov at se din JSON-data direkte skal du derfor gøre én af disse ting:

1. Giv tabellen en en `SELECT`-policy fordi RLS er slået til
2. Læg `apikey` ind som URL-parameter

Eksempel til hurtig test i browseren:

```text
https://din-projekt-ref.supabase.co/rest/v1/students?select=*&apikey=din-publishable-key
```

Når RLS er slået til, er det vigtigt at tabellen også har en `SELECT`-policy. Ellers får du stadig ikke adgang til rækkerne.

</Slide>

## 4) Brug altid headers

Når du laver en enkel `fetch()` til Supabase Data API, skal du starte med:

- `apikey: <SUPABASE_PUBLISHABLE_KEY>`

Hvis du ikke sender den, svarer Supabase med:

```json
{
  "message": "No API key found in request"
}
```

Hvis I senere logger brugere ind med Supabase Auth, kan `Authorization` i stedet være brugerens access token.

Vigtigt:

- brug **ikke** `Publishable Key` som `Bearer` token
- tænkt sådan:
  - `apikey` svarer på: **hvilket projekt vil du hente data fra?**
  - `Authorization: Bearer ...` svarer på: **hvem er brugeren, der er logget ind?**
- `Publishable Key` er altså til projektet, ikke til en bruger-session
- `Anon Key (legacy)` er den ældre nøgle, som mange gamle eksempler stadig viser
- hvis RLS er aktiveret, skal der stadig være policyer, der tillader læsning

</Slide>
<div class="page-break"></div>

<Slide>

## 4b) Lav en `SELECT`-policy

Hvis RLS er slået til, er data ikke automatisk synlige.

Det betyder:

- du kan godt have den rigtige URL
- du kan godt sende `apikey`
- men du får stadig ikke lov at se rækkerne, hvis der ikke findes en læse-policy

Til denne undervisning er den nemmeste løsning at give alle læseadgang til tabellen `students`, fordi sitet kun skal vise indholdet af tabellen.

### Sådan gør du

1. Åbn Supabase Dashboard.
2. Gå til `Table Editor`.
3. Åbn tabellen `students`.
4. Klik på `RLS policies`.
5. Klik `Create policy`.
6. Vælg `Enable read access for all users`.
7. Gem policyen.

### Hvad betyder den?

- policyen gælder læsning af tabellen
- alle brugere må læse rækkerne
- tabellen kan derfor bruges til at vise data på sitet

Det er en god start til test og undervisning. Senere kan I lave mere præcise regler, hvis data ikke skal være offentligt synlige.
