## Når vi laver det i Astro

### Først: ret `.gitignore`

::::caution[Vigtigt]
Opret eller ret `.gitignore` **før** du laver en `.env`-fil.

Ellers risikerer du, at `.env` bliver tracked af Git og i værste fald ender på GitHub sammen med dine nøgler.

Sørg derfor for, at `.env` står i `.gitignore`, inden du opretter filen.
::::

```text
# Miljøfiler
.env

# macOS-filer
.DS_Store

# HUSK at disse skal lægges til dem du har i forvejen
````

### Derefter: lav `.env`

Gem Supabase-oplysninger i en fil der hedder `.env`
(dvs. filnavnet starter med et punktum efterfulgt af `env`, på samme måde som `.gitignore`)

.env

```bash
SUPABASE_URL=https://din-projekt-ref.supabase.co
SUPABASE_PUBLISHABLE_KEY=din-publishable-key
```

- Læg filen i projektets rod (der hvor `package.json` også ligger)
- `.env` må ikke komme med i Git/GitHub
- Her bruger vi almindelige miljøvariabler, fordi hentningen sker i Astro frontmatter

## Sammenhængen mellem `forEach()` og `map()`

Begge metoder går igennem et array **én værdi ad gangen**.

Hvis `data` indeholder rækker fra tabellen `studerende`, så er `student` i begge tilfælde ét objekt ad gangen.

I koden fra slide 4 sender vi hvert `student`-objekt videre til `Student`-komponenten.

Det vigtige er, hvad metoderne giver tilbage:

- `map()` **returnerer et nyt array**
- `forEach()` **returnerer ikke noget, vi kan bruge direkte**

Når vi skriver `<Student student={student} />` inde i `map()`, bliver hver komponent lagt ind i det nye array.
Astro kan derefter vise arrayet direkte i HTML'en.

<div class="columns-2">
  <div>

    <h3><code>.map()</code></h3>

```js
const studentNames = data.map((student) => {
  return student.navn;
});

console.log(studentNames);
```

  </div>

  <div>

<h3>
  <code>forEach()</code>
</h3>

```js
const studentNames = [];

data.forEach((student) => {
  studentNames.push(student.navn);
});

console.log(studentNames);
```

  </div>
</div>

Koden i de to bokse ender altså med det samme resultat:

```js
["Amina", "Jonas", "Sofia"];
```

Forskellen er vejen derhen:

- `map()` bygger og returnerer det nye array for os
- `forEach()` kører bare koden for hvert element, så vi skal selv lave arrayet og bruge `.push()`

I Astro vil vi gerne ende med en samling af komponenter, som kan sættes direkte ind i templaten.

### Derfor bruger vi `map()` her:

- den returnerer et nyt array direkte
- hvert element i det nye array kan være en `<Student />`-komponent
- Astro kan vise det direkte i HTML

I Astro skifter vi bare `student.navn` ud med en komponent:

```astro
{data.map((student) => {
  return <Student student={student} />;
})}
```

Derfor kan den korte Astro-version skrives sådan:

```astro
{data.map((student) => <Student student={student} />)}
```

Pilen `=>` returnerer komponenten direkte her. Det er samme idé som at skrive `return <Student student={student} />;` inde i en `{ ... }`-blok.

`forEach()` er altså ikke forkert. Den er bare mindre praktisk, når målet er at **rendere** komponenter direkte.

## Hvordan viser Astro data i HTML?

Vi laver en komponent til at vise hver studerende:

`StudentCard.astro`

```astro
---
const { student } = Astro.props;
---

<article>
  <h2>{student.first_name} {student.last_name}</h2>
  <p>Klasse: {student.class_name}</p>
</article>
```

Så bruger vi komponenten i vores side:

```astro
---
import StudentCard from "../components/StudentCard.astro";
// ... fetch-kode her
---

<Layout>
  <h1>Studerende</h1>
  {data.map((student) => <StudentCard student={student} />)}
</Layout>
```

- `data` er arrayet med rækker fra tabellen `students`
- `data.map(...)` går igennem én række ad gangen
- `student` er ét objekt ad gangen
- `StudentCard` modtager `student` via `Astro.props`
- Astro bygger HTML'en, før siden bliver sendt til browseren

## Test endpointet i browserkonsollen

Det er vigtigt at kunne se JSON i konsollen før I bygger UI.

```js
const studentsURL =
  "https://din-projekt-ref.supabase.co/rest/v1/students?select=id,first_name,last_name,class_name";
const apiKey = "din-publishable-key";

fetch(studentsURL, {
  headers: {
    apikey: apiKey,
  },
})
  .then((res) => res.json())
  .then((data) => console.log("Students JSON:", data))
  .catch((error) => console.error("Fejl:", error));
```

Hvis du bare åbner endpointet direkte i browseren uden `apikey`, får du typisk:

```json
{
  "message": "No API key found in request"
}
```

:::tip[Kun til testformål]
Vil du se rå JSON i selve browserfanen, kan du lave en hurtig test sådan:

<p style="white-space: nowrap; overflow-x: auto;">
  <code>
    https://
    <span style="color: #15803d; font-weight: 700;">din-projekt-ref</span>
    .supabase.co/rest/v1/
    <span style="color: #15803d; font-weight: 700;">din-tabel</span>
    ?select=*&amp;apikey=
    <span style="color: #15803d; font-weight: 700;">din-publishable-key</span>
  </code>
</p>
Her finder du oplysningerne i Supabase under dit projekt:

- <code style="color: #15803d; font-weight: 700;">din-projekt-ref</code>:
  `Project Settings → Data API → API URL`
- <code style="color: #15803d; font-weight: 700;">din-tabel</code>: `Table
  Editor → vælg din tabel` og brug tabellens navn
- <code style="color: #15803d; font-weight: 700;">din-publishable-key</code>:
  `Project Settings → API Keys → Publishable Key`

:::

I rigtig kode bør du stadig bruge `fetch()` med headers.

Hvis tabellen bruger RLS, skal du også have en `SELECT`-policy, ellers bliver rækkerne ikke vist.

## Øvelse: Opret din første `students`-tabel og vis data i konsollen

1. Gå tilbage til Supabase og opret tabellen `students` (hvis den ikke findes):
   - `id` (`uuid`, primary key, default `gen_random_uuid()`)
   - `first_name` (`text`, not null)
   - `last_name` (`text`, not null)
   - `email` (`text`, unique)
   - `class_name` (`text`)

2. Indsæt 2–3 testrækker i tabel-editoren.
3. Brug din endpoint med det rigtige projekt-id i browserens konsol:
   - Erstat `din-projekt-ref` og `din-publishable-key` med dine egne værdier.
   - Du skal se et array i konsollen (`[]` hvis ingen rækker).

4. Spørgsmål til refleksion:
   - Hvad sker der med resultatet, hvis du ændrer `select=*`?
   - Hvad sker der, hvis du laver `select=first_name`?
   - Hvordan ændrer rækkefølgen sig med `order=first_name.asc`?
