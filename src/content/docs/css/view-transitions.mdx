## TL;DR: View Transitions

<p class="pl-lead">View Transitions gør skift mellem to visninger til en visuel overgang.</p>

Vi arbejder med **to HTML-sider og almindelige links**. Eksemplet kræver ingen JavaScript.

Efter forløbet kan du:

- aktivere overgange mellem sider på samme website,
- forbinde et element på den gamle side med et på den nye,
- tilpasse varigheden og respektere reduceret bevægelse.

<span slot="takeaway">Navigationen skal fungere, også når browseren springer animationen over.</span>
</Slide>

## Browseren forbinder før og efter

1. Browseren fastholder et billede af den gamle visning — et **snapshot**.
2. Den nye side bliver indlæst.
3. Browseren animerer overgangen mellem den gamle og den nye visning.

Som udgangspunkt toner den gamle visning ud, mens den nye toner ind. Det kaldes en **crossfade**.

En almindelig CSS-`transition` forbinder ændrede egenskaber på et element. View Transitions kan også forbinde visninger fra to forskellige HTML-dokumenter.

<span slot="takeaway">Du bygger begge sider som normalt. Browseren håndterer den visuelle overgang.</span>
</Slide>

## Mellem sider eller på samme side?

| Situation | Hvordan starter overgangen? |
| --- | --- |
| **Mellem HTML-dokumenter** — cross-document | Et link og CSS-reglen `@view-transition`. |
| **En ændring i samme dokument** — same-document | JavaScript kan bruge `document.startViewTransition()` omkring ændringen. |

**Her arbejder vi med den første løsning.** Vi bruger et projektkort og en separat projektside.

Browserstøtten er forskellig for de to løsninger. Støtte til JavaScript-metoden betyder ikke nødvendigvis støtte til overgange mellem dokumenter.

<span slot="takeaway">View Transitions er ikke det samme som scrollanimationer med <code>view()</code>.</span>
</Slide>

## Start med to sider og ét stylesheet

Opret tre filer i samme mappe: `index.html`, `projekt.html` og `style.css`. HTML-filerne her er klar til kopiering. CSS samles på slide 11.

<details class="pl-reveal">
<summary>index.html – oversigten</summary>

```html
<!doctype html>
<html lang="da">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Projekter</title>
  <link rel="stylesheet" href="style.css" />
</head>
<body>
  <main>
    <h1>Projekter</h1>
    <a class="projektkort" href="projekt.html">
      <div class="motiv motiv-lille" aria-hidden="true">A</div>
      <h2 class="projekttitel">Projekt A</h2>
    </a>
  </main>
</body>
</html>
```

</details>
<details class="pl-reveal">
<summary>projekt.html – projektsiden</summary>

```html
<!doctype html>
<html lang="da">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1" />
  <title>Projekt A</title>
  <link rel="stylesheet" href="style.css" />
</head>
<body>
  <main>
    <a href="index.html">Tilbage til projekter</a>
    <h1 class="projekttitel">Projekt A</h1>
    <div class="motiv motiv-stor" aria-hidden="true">A</div>
    <p>Her kan du læse om projektets idé og resultat.</p>
  </main>
</body>
</html>
```

</details>

<span slot="takeaway">Brug samme server til begge sider. Åbn ikke filerne direkte med <code>file://</code>.</span>

## Aktivér på begge sider

Skriv i den fælles `style.css`:

```css
@view-transition {
  navigation: auto;
}
```

- **`@view-transition`** er en CSS-regel for overgange ved navigation.
- **`navigation: auto`** tilmelder dokumentet til overgange ved understøttet navigation.
- **Begge sider skal tilmelde sig.** Derfor indlæser begge HTML-filer den samme CSS-fil.

Klik på et almindeligt link mellem siderne. Et sideskift via adresselinjen er ikke den samme afprøvning.

<span slot="takeaway">Uden browserstøtte virker linket stadig, men siden skifter uden denne animation.</span>
</Slide>

## Forbind motivet med et navn

```css
.motiv {
  view-transition-name: projektmotiv;
}
```

**`view-transition-name`** giver elementet sin egen del af overgangen.

Navnet `projektmotiv` forbinder det lille motiv på oversigten med det store motiv på projektsiden. Browseren kan animere forskellen i placering og størrelse.

**Navnet skal være unikt på hver side.** To synlige elementer med samme navn i samme dokument kan få overgangen til at blive sprunget over.

<span slot="takeaway">Samme navn på tværs af siderne — kun ét element med det navn på hver side.</span>
</Slide>
<div class="page-break"></div>

{/* Slide 9: Pseudo-elementer og varighed */}

## Styr varigheden med CSS

```css
::view-transition-group(projektmotiv) {
  animation-duration: 400ms;
}
```

**`::view-transition-group()`** er et pseudo-element: noget browseren laver til overgangen, som du kan style uden at skrive mere HTML.

| Selector | Hvad vælger den? |
| --- | --- |
| `::view-transition-group(projektmotiv)` | Gruppen for det navngivne motiv, bl.a. bevægelse og størrelse. |
| `::view-transition-old(projektmotiv)` | Den gamle udgave af motivet. |
| `::view-transition-new(projektmotiv)` | Den nye udgave af motivet. |

`400ms` er 0,4 sekunder. Start med gruppens varighed; browseren leverer selve standardanimationen.

</Slide>

## Bevar navigationen uden bevægelsen

Placér denne regel efter den almindelige aktivering:

```css
@media (prefers-reduced-motion: reduce) {
  @view-transition {
    navigation: none;
  }
}
```

`prefers-reduced-motion` aflæser brugerens ønske om mindre bevægelse. `navigation: none` fravælger overgangen mellem dokumenterne.

Linkene og indholdet fungerer stadig. Denne regel skal også være i den fælles CSS, som begge sider indlæser.

<span slot="takeaway">Overgangen er en ekstra visuel hjælp. Den må ikke være nødvendig for at forstå eller bruge siden.</span>
</Slide>

## Lad titlen følge med selvstændigt

Brug de tre filer fra eksemplet. Motivets overgang virker allerede.

**Jeres mål:** Titlen “Projekt A” skal også forbindes mellem siderne, men have **sin egen overgang på 250ms**. Motivets overgang skal fortsat være 400ms.

- Vælg titlen via den eksisterende klasse `projekttitel`.
- Giv titlen en selvstændig identitet i overgangen.
- Bevar reduceret bevægelse og almindelige links.

**Resultat:** To elementer, der hver kan følges fra oversigt til detalje. Vis begge retninger, og forklar, hvorfor de skal have forskellige navne.

<details class="pl-reveal">
<summary>Hint</summary>

Hvilken regel forbinder motivet på de to sider? Hvad skal ændres, så titlen får sin egen gruppe, og hvilken selector styrer gruppens varighed?

</details>
<details class="pl-reveal">
<summary>Løsningsforslag efter jeres forsøg</summary>

Tilføj i `style.css`:

```css
.projekttitel {
  view-transition-name: projekttitel;
}
::view-transition-group(projekttitel) {
  animation-duration: 250ms;
}
```

Der er kun én `projekttitel` på hver side. Den kan derfor matches på tværs, selv om HTML-tagget er `h2` på oversigten og `h1` på detaljesiden. Motivet beholder sit navn `projektmotiv`.

</details>

## Kan brugeren følge begge elementer?

| Niveau | Tegn på forståelse |
| --- | --- |
| På vej | Linkene virker, men kun motivet har sin egen overgang, eller navne er dublerede. |
| Det fungerer | Titel og motiv har forskellige navne og de aftalte varigheder. |
| Du kan forklare det | I forklarer matchningen, viser begge retninger og afprøver reduceret bevægelse. |

Byt betjening. Brug både mus og tastatur. Afprøv også et smalt vindue.

**Ret mindst én ting** i jeres løsning eller forklaring, og gentag afprøvningen. Hvis animationen mangler, kontrollér browserstøtte, samme origin, CSS på begge sider og unikke navne.

## Tre regler at huske

1. **`@view-transition`** aktiverer overgangen på begge sider.
2. **`view-transition-name`** forbinder et element før og efter.
3. **`::view-transition-group()`** lader dig tilpasse gruppens animation.

**Forklar selv:** Hvad kan gå galt, hvis to projektkort på samme side begge får `view-transition-name: projektmotiv`?

<details class="pl-reveal">
<summary>Se forklaringen efter dit eget bud</summary>

Navnet er ikke længere unikt i dokumentet. Browseren kan springe overgangen over. Brug forskellige navne til forskellige elementer, og match det relevante navn på destinationssiden.

</details>
