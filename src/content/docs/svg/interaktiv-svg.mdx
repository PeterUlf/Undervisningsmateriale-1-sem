## Tre sprog samarbejder

**Del to bud fra samtalen.** Sammenhold dem derefter med denne kæde:

```text
HTML: Et tekstpunkt åbnes eller lukkes
                  ↓ toggle
JavaScript: Find det åbne punkt, og læs data-position
                  ↓ dataset.position
SVG: Får fx data-position="second"
                  ↓ CSS-selector
CSS: Flyt og vis spotlyset
```

HTML styrer åbning og lukning. JavaScript overfører valget. CSS bestemmer, hvor spotlyset vises.

**Når alt er lukket:** JavaScript fjerner SVG’ens `data-position`, og CSS skjuler spotlyset. Det løser samtalens anden situation.

## Browseren åbner og lukker teksten

En **accordion** er en samling tekstafsnit, du kan folde ud. Her bygges den med `<details>` og `<summary>`:

```html
<details
  class="accordion-item"
  id="details-first"
  data-position="first"
  name="fest"
>
  <summary>Øl</summary>
  <div>
    <p>Her kan du købe alkoholfri øl.</p>
  </div>
</details>
```

- `<summary>` er overskriften, du aktiverer med mus eller tastatur.
- `<details>` får attributten `open`, når indholdet vises.
- Alle tre punkter har `name="fest"`: **højst ét er åbent ad gangen**. Alle kan godt være lukkede.

JavaScript er altså ikke nødvendigt for at folde teksten ud. `open="false"` lukker heller ikke et punkt: Attributten skal fjernes.

</Slide>

## Hvad betyder de fire attributter?

| Attribut på punktet Øl   | Opgave                                                    |
| ------------------------ | --------------------------------------------------------- |
| `class="accordion-item"` | Fælles klasse, så vi kan finde og style punkterne.        |
| `id="details-first"`     | Unik identifikation af netop dette element.               |
| `name="fest"`            | Grupperer punkterne, så browseren kun åbner ét ad gangen. |
| `data-position="first"`  | Vores egen værdi, som skal forbindes med en position.     |

På **Musik** bruges `id="details-second"` og `data-position="second"`. På **Merch** bruges `details-third` og `third`.

<div class="slide-takeaway">

`data-*` gemmer egne data på et element. **`first`, `second` og `third` er selvvalgte tekstværdier**; de er ikke koordinater og gør ikke noget af sig selv.

</div>

## Én SVG-fil, tre dele på siden

`band.svg` indeholder grupper med id’erne `baggrund`, `logoer` og `spot`. Et `<use>` viser en genbrugt udgave af den valgte gruppe:

```html
<svg class="event-map" viewBox="0 0 1344 768">
  <use class="scene" href="./SVG/band.svg#baggrund"></use>
  <use class="logo" href="./SVG/band.svg#logoer"></use>
  <use class="spot" href="./SVG/band.svg#spot"></use>
</svg>
```

`./SVG/band.svg` er filen. `#spot` peger på `id="spot"` i filen. Klassen `.spot` sidder på sidens `<use>`, som vi flytter og skjuler med CSS. Det sidste lag tegnes oven på de tidligere.

**Praktisk:** Brug Live Server, og behold SVG-filen på samme website. Her er stierne gjort ens med `./`; originalens baggrund bruger `/SVG/…`, som starter fra domænets rod.

</Slide>

## Giv elementerne navne i JavaScript

Browserens model af sidens elementer kaldes **DOM**. `document` giver adgang til den. `querySelector()` finder det første element, som passer til en CSS-selector:

```javascript
const eventMap = document.querySelector(".event-map");

if (eventMap) {
  const firstDetails = document.querySelector("#details-first");
  const secondDetails = document.querySelector("#details-second");
  const thirdDetails = document.querySelector("#details-third");
  // Her kommer funktionen og de tre event listeners.
}
```

`const` giver en værdi et fast navn; elementets attributter kan stadig ændres. Hvis SVG’en ikke findes, får vi `null` — ingen værdi. `if (eventMap)` sørger for kun at køre blokken på sider med SVG’en.

I `svg.html` står `<script src="./script.js"></script>` lige før `</body>`. Derfor findes elementerne allerede, når denne kode kører.

</Slide>

## Find det åbne punkt hver gang

```javascript title="Uden const – find elementerne direkte"
function updateSvgPosition() {
  if (document.querySelector(".accordion-item[open]")) {
    document.querySelector(".event-map").dataset.position =
      document.querySelector(".accordion-item[open]").dataset.position;
  } else {
    delete document.querySelector(".event-map").dataset.position;
  }
}
```

```javascript title="Med const – gem elementerne under navne"
function updateSvgPosition() {
  const eventMap = document.querySelector(".event-map");
  const openDetails = document.querySelector(".accordion-item[open]");
  if (openDetails) {
    eventMap.dataset.position = openDetails.dataset.position;
  } else {
    delete eventMap.dataset.position;
  }
}
```

To udgaver af samme **funktion** – brug kun én. Begge kopierer `data-position` fra det åbne punkt til SVG’en og fjerner attributten, når alle punkter lukkes.

## Kør funktionen, når et punkt skifter tilstand

En **event** er browserens besked om, at noget er sket. `toggle` kommer, når et `<details>` er åbnet eller lukket. En **event listener** lytter efter beskeden:

```javascript
firstDetails.addEventListener("toggle", updateSvgPosition);
secondDetails.addEventListener("toggle", updateSvgPosition);
thirdDetails.addEventListener("toggle", updateSvgPosition);

updateSvgPosition();
```

De tre listeners står efter funktionen, stadig inde i `if (eventMap)`. Ved hvert skift finder funktionen det punkt, der **nu** er åbent; både åbning og lukning kan udløse den.

**To skrivemåder:** Uden `()` afleverer vi funktionen til senere. Med `()` kører vi den med det samme.

Det sidste kald er en lille tilføjelse til originalen: Det synkroniserer starttilstanden, også hvis et punkt har `open` fra begyndelsen.

</Slide>

## CSS flytter selve spotlyset

Her er de relevante regler fra `style.css`, forkortet til position og synlighed:

<div class="slide-split">
<div>

```css
.event-map {
  --z: 0;
}
.spot {
  translate: var(--x) var(--y);
  opacity: var(--z);
  transition: 0.5s;
}
```

</div>
<div>

```css
.event-map[data-position="second"] {
  --x: 34%;
  --y: -2%;
  --z: 1;
}
```

Reglen matcher SVG’en, når JavaScript har skrevet `data-position="second"`.

</div>
</div>

De tre **custom properties** arves af `.spot`: `--x` og `--y` flytter vandret og lodret; `--z` bruges til gennemsigtighed, hvor **0 skjuler** og **1 viser**. Navnet `--z` er ikke en z-akse.

Når attributten fjernes, gælder `--z: 0` igen. Demoen på næste slide giver også `--x` og `--y` startværdien `0%`, så de altid har en værdi.

</Slide>

<summary>Vis hint</summary>

## Test kæden, ét led ad gangen

<p class="slide-meta">
  3 minutter · to og to · vis jeres arbejde, og ret én eventuel fejl

Test **genindlæs → Info → Øl → luk Øl** med mus og derefter tastatur. Sammenlign med kriterierne på opgavesliden.

| Det, I ser                                  | Det næste sted at kigge                                                           |
| ------------------------------------------- | --------------------------------------------------------------------------------- |
| Flere tekstpunkter kan stå åbne             | Har de præcis samme `name`?                                                       |
| SVG’en får ingen `data-position`            | Kontrollér id, selector og `toggle`-listener. Se efter fejl i browserens Console. |
| SVG’en får `fourth`, men spottet vises ikke | Matcher CSS værdien `fourth`, og sættes `--z: 1`?                                 |
| Spottet bliver stående, når alt lukkes      | Fjernes attributten i `else`, og er grundværdien `--z: 0`?                        |

Højreklik på illustrationen, vælg **Inspect/Undersøg**, og find `<svg class="event-map">`. Hold øje med `data-position`, mens I skifter punkt.

**Hurtigt færdig?** Flyt Info op før Øl i HTML. Forudsig og afprøv, om forbindelsen stadig virker uden ændringer i JavaScript og CSS. Begrund hvorfor.
